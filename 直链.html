这是什么
Direct Link
把图片、视频、音频、字体、ZIP 上传到你自己的 GitHub 仓库，并自动生成可直接使用的直链。文件存在你自己的仓库里，不经过第三方服务器。
数据只存在本机
GitHub Token、仓库设置、偏好和上传记录都只保存在这台设备的浏览器里。清除网站数据、删除主屏幕 App 或换设备后，需要重新填写 Token 并设置偏好。仓库文件的收藏和标签可以同步到仓库里，见「同步标签到仓库」。

账户与直链
GitHub Token
Token 需要有仓库读写权限。如果要在 App 里删除整个仓库，还需要给 Token 勾选 delete_repo 权限，否则会提示删除失败。请不要把 Token 发给别人。
API 代理 / 图片代理（可选）
访问 GitHub 不稳定时可以填写自己的代理地址。不填则直接连接 GitHub 和 jsDelivr。把别人网站的图片转存进来时，如果对方不允许跨域读取或有防盗链，就需要填「图片代理」。
代理部署代码
在 Cloudflare 新建一个 Worker，粘贴代码并部署。「API 代理」填 https://你的域名.workers.dev，「图片代理」填 https://你的域名.workers.dev/img。想防止别人蹭用，把代码开头的 KEY 改成一串随机字符，两个地址都在域名后面加 /这串字符。之前分开部署的两个 Worker 不用动，继续能用。
API 代理 + 图片代理（一个 Worker）
// 一个 Worker 同时当 API 代理和图片代理
// API 代理地址：https://xxx.workers.dev      图片代理地址：https://xxx.workers.dev/img
// 防蹭用（可选）：KEY 填一串随机字符（只用字母和数字），两个地址都要在域名后面加 /这串字符
const KEY = '';

const CORS = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Methods': 'GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS',
  'Access-Control-Expose-Headers': 'ETag, Link, Retry-After, X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset, X-RateLimit-Resource, X-Cache, Content-Type, Content-Length, Content-Range, Accept-Ranges',
  'Access-Control-Max-Age': '86400'
};
const DEFAULT_ALLOW = 'Authorization, Accept, Content-Type, X-GitHub-Api-Version, Cache-Control, If-None-Match';
// 本机和内网地址不代理
const BLOCKED = /^(\[|(127|10|0)\.\d+\.\d+\.\d+$|192\.168\.\d+\.\d+$|169\.254\.\d+\.\d+$|172\.(1[6-9]|2\d|3[01])\.\d+\.\d+$)|(^|\.)(localhost|local|internal)\.?$/i;
const MAX_BYTES = 50 * 1024 * 1024;
const MAX_HOPS = 5;
const TIMEOUT_MS = 15000;   // 等上游返回响应头的时间上限（开始传内容后不再计时）
const IMAGE_TYPE = /^(image\/|application\/octet-stream|binary\/octet-stream)/i;
const NOREF = new Set();    // 记住「带来源页会被拒」的域名，下次直接不带，省一次请求
// 防盗链严格的站要求固定的来源页；其他站默认用图片自己的域名
const REFERERS = [
  [/(^|\.)sinaimg\.cn$/, 'https://weibo.com/'],
  [/(^|\.)pximg\.net$/, 'https://www.pixiv.net/'],
  [/(^|\.)hdslb\.com$/, 'https://www.bilibili.com/'],
  [/(^|\.)zhimg\.com$/, 'https://www.zhihu.com/'],
  [/(^|\.)doubanio\.com$/, 'https://www.douban.com/'],
  [/(^|\.)qpic\.cn$/, 'https://mp.weixin.qq.com/'],
  [/(^|\.)csdnimg\.cn$/, 'https://blog.csdn.net/'],
  [/(^|\.)byteimg\.com$/, 'https://juejin.cn/']
];

const reply = (body, status, type) => new Response(body, { status: status, headers: { ...CORS, 'Content-Type': type || 'text/plain;charset=UTF-8' } });
const jsonMsg = (message, status) => reply(JSON.stringify({ message: message }), status, 'application/json');
// 只代理 http(s)、默认端口、不带账号密码的公网地址
const allowed = url => /^https?:$/.test(url.protocol) && !BLOCKED.test(url.hostname) && !url.username && !url.password && (!url.port || url.port === '80' || url.port === '443');
// 转发前去掉能识别访问者的请求头，不把用户的 IP、Cookie 交给 GitHub
const stripIdentity = headers => Array.from(headers.keys()).forEach(k => { if (/^(cf-|x-forwarded-|sec-|cookie$|origin$|referer$|host$|x-real-ip$|true-client-ip$|cdn-loop$)/i.test(k)) headers.delete(k); });

export default {
  async fetch(request) {
    if (request.method === 'OPTIONS') {
      const allow = request.headers.get('Access-Control-Request-Headers') || DEFAULT_ALLOW;
      return new Response(null, { status: 204, headers: { ...CORS, 'Access-Control-Allow-Headers': allow, 'Vary': 'Access-Control-Request-Headers' } });
    }
    try {
      const u = new URL(request.url);
      let path = u.pathname.replace(/\/{2,}/g, '/');   // 地址末尾多写了 / 时，拼出来会是 //user
      let base = u.origin;
      if (KEY) {
        if (path !== '/' + KEY && path.indexOf('/' + KEY + '/') !== 0) return jsonMsg('forbidden', 403);
        path = path.slice(KEY.length + 1) || '/';
        base += '/' + KEY;
      }
      const route = path.length > 1 ? path.replace(/\/+$/, '') : path;
      return route === '/img' ? await proxyImage(request, u) : await proxyApi(request, u, path, base);
    } catch (e) {
      // 出错时也带上 CORS，页面才看得到真实原因
      return jsonMsg('proxy error: ' + e.message, 502);
    }
  }
};

/* ----- GitHub API ----- */
async function proxyApi(request, u, path, base) {
  // 没带 Token 的请求会共用出口 IP 的匿名额度，很容易被别人耗光
  if (!request.headers.get('Authorization')) return jsonMsg('Authorization required', 401);
  const headers = new Headers(request.headers);
  stripIdentity(headers);
  headers.set('User-Agent', 'direct-link-proxy');
  const hasBody = request.method !== 'GET' && request.method !== 'HEAD';
  // 不在这里跟随重定向：带请求体的 PUT/POST 遇到 307 会因为流不能重放而失败，交给浏览器按新地址重发
  const res = await fetch('https://api.github.com' + path + u.search, {
    method: request.method,
    headers: headers,
    body: hasBody ? request.body : undefined,
    redirect: 'manual'
  });
  const out = new Headers(res.headers);
  Object.keys(CORS).forEach(k => out.set(k, CORS[k]));
  const loc = out.get('Location');
  if (loc) out.set('Location', loc.replace('https://api.github.com', base));   // 重定向继续走代理
  return new Response(res.body, { status: res.status, statusText: res.statusText, headers: out });
}

/* ----- 图片 ----- */
// 手动逐跳跟随重定向，每一跳都检查目标地址
async function timedFetch(url, init) {
  const ac = new AbortController();
  const timer = setTimeout(() => ac.abort(), TIMEOUT_MS);
  try { return await fetch(url, { ...init, signal: ac.signal }); }
  catch (e) { throw ac.signal.aborted ? Object.assign(new Error('upstream timeout'), { status: 504 }) : e; }
  finally { clearTimeout(timer); }
}
async function fetchFollow(url, request, ref) {
  const range = request.headers.get('Range');
  for (let hop = 0; hop <= MAX_HOPS; hop++) {
    if (!allowed(url)) throw Object.assign(new Error('blocked'), { status: 403 });
    const headers = { 'User-Agent': 'Mozilla/5.0', 'Accept': 'image/*,*/*;q=0.8' };
    if (ref) headers['Referer'] = ref;
    if (range) headers['Range'] = range;
    const init = { method: request.method, headers: headers, redirect: 'manual' };
    if (request.method === 'GET') init.cf = { cacheEverything: true, cacheTtlByStatus: { '200-299': 86400, '300-599': -1 } };   // 成功的缓存一天，失败的不缓存
    const res = await timedFetch(url.href, init);
    const loc = res.headers.get('Location');
    if (res.status >= 300 && res.status < 400 && loc) {
      if (res.body) await res.body.cancel();
      url = new URL(loc, url);
      continue;
    }
    return res;
  }
  throw new Error('too many redirects');
}
// 没有 Content-Length 的响应边传边数，超过上限就中断
function limited(body, max) {
  let n = 0;
  return body.pipeThrough(new TransformStream({
    transform(chunk, ctl) { n += chunk.byteLength; if (n > max) ctl.error(new Error('too large')); else ctl.enqueue(chunk); }
  }));
}
async function proxyImage(request, u) {
  if (request.method !== 'GET' && request.method !== 'HEAD') return reply('method not allowed', 405);
  let target;
  try { target = new URL(u.searchParams.get('url')); } catch (e) { return reply('bad url', 400); }
  if (!allowed(target)) return reply('blocked', 403);
  try {
    // 先带来源页取一次，被拒（401/403）再不带来源页重试一次
    const rule = REFERERS.find(r => r[0].test(target.hostname));
    const referers = NOREF.has(target.hostname) ? [''] : [rule ? rule[1] : target.origin + '/', ''];
    let res, used;
    for (const ref of referers) {
      used = ref;
      res = await fetchFollow(target, request, ref);
      if (res.status !== 401 && res.status !== 403) break;
      if (ref && res.body) await res.body.cancel();
    }
    if (referers.length > 1 && !used && res.status !== 401 && res.status !== 403) {
      if (NOREF.size >= 500) NOREF.clear();
      NOREF.add(target.hostname);
    }
    const type = res.headers.get('Content-Type');
    if (res.ok && type && !IMAGE_TYPE.test(type)) { if (res.body) await res.body.cancel(); return reply('not an image', 415); }
    const len = Number(res.headers.get('Content-Length'));
    if (len > MAX_BYTES) { if (res.body) await res.body.cancel(); return reply('too large', 413); }
    const out = new Headers(res.headers);
    ['set-cookie', 'vary', 'alt-svc'].forEach(k => out.delete(k));
    Object.keys(CORS).forEach(k => out.set(k, CORS[k]));
    out.set('X-Content-Type-Options', 'nosniff');
    out.set('Content-Security-Policy', "default-src 'none'; sandbox");   // 直接用浏览器打开代理地址时，网页类内容不会执行
    out.set('X-Cache', res.headers.get('cf-cache-status') || 'UNKNOWN');   // HIT 表示命中了 Cloudflare 缓存
    out.set('Cache-Control', res.ok ? 'public, max-age=86400' : 'no-store');   // 失败的响应不让浏览器缓存
    const body = res.body && !len ? limited(res.body, MAX_BYTES) : res.body;
    return new Response(body, { status: res.status, headers: out });
  } catch (e) {
    return reply('fetch failed: ' + e.message, e.status || 502);
  }
}
直链固定到提交版本
开启后，直链里会带上本次提交的版本号，之后覆盖同名文件也不会改变这个链接的内容。关闭则链接跟随分支，覆盖同名文件后，链接指向的内容会更新（CDN 缓存可能有延迟）。
上传规则
隐私：去除 EXIF
默认开启。JPEG / PNG / WebP 上传前会无损删掉拍摄位置、设备型号、时间等信息，画质不变，照片方向和颜色配置会保留。HEIC、AVIF 无法无损处理，会在结果行提示；开启「HEIC 转 JPG」后转出来的 JPG 不带 EXIF。
支持的内容
图片、视频、音频、字体和 ZIP。视频放在 videos/、音频放在 audio/；超过 20MB 的视频走 GitHub raw 直链，部分场景可能无法直接在网页里播放。字体始终保持原文件名和原位置，不受「文件名」「文件夹」设置影响。
大小限制
单个文件最大 99MB，超过的会被跳过。超过 20MB 的文件 jsDelivr 不支持，会自动改用 GitHub raw 直链。导入 ZIP 压缩包时，压缩包本身不能超过 400MB。
自动重试
网络波动、超时、服务器 5xx、提交冲突、被限流这类临时问题会自动重试。Token 错误、仓库不存在、文件过大这类确定的错误不会重试，需要修正后在结果列表里手动点「重试」。
重复文件
8MB 以内的文件会先查重，避免传重复内容；更大的文件为了不占内存，跳过查重。
并发与合并提交
多个文件会同时上传（最多 3 个），传完的文件合并成一次 Git 提交，比逐个提交快得多。GitHub 对「创建内容」的请求有频率限制，遇到限流会自动放慢并重试；很多个小文件时速度主要受这个限制，不是网速。
上传过程中
批量上传时尽量保持页面打开。需要切到后台或锁屏时，建议打开「后台保活」。
设置说明
上传前处理
关闭：原样上传。压缩：长边超过 2560px 的图片会等比缩小并重新压缩。WebP：转成 WebP，体积通常更小。小于 30KB 的图片，以及 GIF、SVG、ICO，不会被处理。
当前浏览器：检测中…
HEIC 转 JPG
iPhone 相册里的 HEIC / HEIF 图片在上传前转成 JPG，这样大多数网页和软件都能直接打开。
文件名 / 文件夹
文件名：原名保持原文件名；随机会生成一串随机字符，避免重名和暴露原名。文件夹：不分是全部放在同一层；按月会按上传月份归档，例如 2026-10。这两项只作用于图片。
复制格式 / 自动复制
复制格式可选直链、Markdown、HTML。开启「上传后自动复制」后，上传成功会自动按所选格式复制到剪贴板。
上传后跳到资源库
只有全部文件都上传成功才会跳转；有失败时会留在当前页，方便查看失败原因并重试。
同步标签到仓库
开启后，仓库文件的收藏和标签会在修改几秒后自动保存到仓库里的 .directlink/meta.json，换手机或浏览器后打开仓库页就能看到同样的标签，不用靠备份。每次同步会在仓库里多一条提交记录；这个文件不会出现在文件列表里，也不影响直链。两台设备同时改过时，标签取并集，所以在别处刚删掉的标签可能被带回来。仓库页「…」菜单里可以手动「同步标签与收藏」。关闭后只存在这台设备上。
资源库与仓库
按标签全选
先点「标签」选一个标签，再点一次「标签」，菜单第一项就是「全选此标签」。会选中当前筛选下看得到的全部项目，之后可以直接批量移动、下载、删除。仓库页的标签筛选会跨文件夹，整个仓库里带这个标签的文件都会被选中。
在仓库里定位
在资源库里只选中一张图，点「标签」按钮，面板里有「在仓库里定位」，会切到仓库页、进入它所在的文件夹并高亮。只能定位当前仓库里的文件。
最近删除
在仓库页或资源库删掉的仓库文件，会记在首页的「最近删除」里，30 天内可以恢复：点一条选「恢复」，或点右上角「全部恢复」。恢复会把文件放回原来的位置，收藏、标签和资源库记录一起还原；原位置已经有同名文件的会跳过，不会被覆盖。「清空」只清这份列表，不会动仓库。这份列表只存在这台设备上。
批量重命名
在仓库页或资源库选中 2 个以上的文件，点「重命名」，可以按规则加前缀、加后缀、按序号命名或查找替换。扩展名保持不变，弹窗里会先预览结果，一次提交完成，改完可以撤销。改名后原来的直链会失效。
自定义复制格式
设置里的「自定义模板」可以写自己的复制格式：{url} 是直链，{name} 是文件名，{stem} 是不带扩展名的文件名，{ext} 是扩展名。例如 url("{url}")。保存后复制格式会切到「自定义」，换回直链、Markdown 或 HTML 就恢复原样。
导出链接清单
仓库页的「更多工具」和资源库的菜单里都有「导出链接清单」，可以按选中、当前列表或全部，导出成纯链接、按当前复制格式、JSON 或 CSV 文件，方便备份、搬家和批量替换。
替换历史
「替换链接」页下面会记下每次替换（包括表情包转存）生成的新文件，不会自动删除，一直留到你自己移除或清空。点一条可以重新下载、复制「旧链接 → 新直链」的对照表，或从列表移除。内容只存在这台设备的浏览器里，不会上传；导出备份时会一起带上（备份文件会因此变大），导入时只补回缺少的，已有的不会被覆盖。没有备份的话，清除网站数据会把它一起清掉。
文件管理
按文件夹逐层浏览仓库文件，右上角可以新建文件夹、切换排序（手动 / 名称 / 大小 / 类型）、查看历史。点文件可预览（图片、文本代码）、重命名、移动、手动上移下移（仅手动排序）、删除；文件夹右侧的「···」可以重命名、移动整个文件夹或删除它，里面的文件一起处理，都能撤销或在「最近删除」恢复。上传时选一个文件可指定路径，选多个会保留原名传到当前文件夹，一次提交。历史记着这个仓库最近 30 次操作，移动类操作可以撤销。排序方式、手动顺序和历史只存在这台设备上。
检测与提醒
检测剪贴板图片
打开 App 时检查剪贴板里有没有图片，有的话提示你直接上传。系统可能会弹出「允许粘贴」的确认，这是系统的隐私保护，选允许即可。
仓库页检测失效链接
仓库页「…」菜单里的「检测失效链接」，会逐个打开仓库文件的直链，打不开的标红「失效」，只有 jsDelivr 没同步的标灰「CDN 未同步」。检测结果只保存在本次打开期间。打开「自动检测失效链接」后，每个仓库读取完文件会隔 7 天自动检测一次，只有发现失效时才提示。文件在仓库里不代表直链一定能用，私有仓库、特殊字符的文件名都可能打不开。
仓库页查找重复文件
仓库页「…」菜单里的「查找重复文件」，按文件内容找出完全相同的文件（不用下载任何文件）。每组保留路径最短的一份，其余标灰「重复」，可以一键选中后删除。删除副本后，用那些路径的直链会失效，先确认没有地方在用。检测失效链接也可以只检测当前文件夹，或多选后只检测选中的文件。
仓库页更多工具
仓库页「…」→「更多工具」里有四个：查找相似图片（在手机上算图片指纹，第一次要下载图片，结果会缓存）；扫描未被引用的文件（导入你的 HTML、JSON 等文件，找出仓库里没被用到的图片）；导出表情包 JSON（含义取自文件名，分类取自文件夹）；CDN 线路（测速，之后复制的链接会换成选定的线路，不会改动已有的记录）。另外，替换文件那页选文件时会自动识别表情包，不用另外点按钮：Word（.docx，每段一条「含义：链接」，需要 iOS 16.4 及以上）、带含义或分类的 JSON（里面是链接，或直接内嵌的 base64 图片都行，也认 {"含义": "链接"} 的写法）、几乎每行都是「含义：链接」的文本（.txt / .md / .csv，也认 Markdown 图片写法）。识别为表情包后，按分类建文件夹、用含义当文件名转存；JSON 输出换好直链的新 JSON，Word 和文本输出整理好的新 JSON，分类取自单独成行的标题，没有标题就用文件名。其他文件照旧原样替换链接。
自动检测失效链接
打开资源库时自动检查已上传的链接是否还能访问，仓库页也会按同样的间隔检查仓库文件的直链，会产生额外的网络请求。不需要时可以关闭。
后台保活
开启后会循环播放无声音频，让 iOS 不要把页面挂起，锁屏或切到其他 App 时上传也能继续。开启期间可能会打断其他 App 正在播放的音乐或播客。控制中心会出现「后台保活中」的播放卡片，这是正常现象；会增加耗电。如果提示「点一下屏幕即可启用后台保活」，点一下屏幕即可。
屏幕常亮
上传时阻止屏幕自动锁定。只在页面处于前台时有效，同样会增加耗电。据我所知，较旧的 iOS 版本在主屏幕网页里可能不生效。
上传完成通知
只在 App 不在前台时发送，用来告诉你成功、失败、跳过各多少个。需要先授权通知。iPhone 上需要把本页添加到主屏幕再打开，而且单个 HTML 文件在部分 iOS 环境下发不了系统通知，请以「发送测试通知」的结果为准。可以点「发送测试通知」检查是否正常。
存储与保存文件
存储
显示所有账号名下每个仓库占用的空间，可以按大小或最近更新排序。数据来自 GitHub，包含历史提交，刚上传或刚删除后数字可能有延迟。
下载与导出
图片下载时，在弹出的面板里选「存储图像」会进入相册；其他文件选「存储到“文件”」再选保存位置。也可以打包成 ZIP，或导出每行一个直链的 .txt 清单。
仓库规则
超过 1 GB 会怎样
1 GB 是 GitHub 的建议上限，不是硬限制。用量到 80% 会提醒，超过后进度条变红。在超过 1 GB 的仓库里上传时，会先弹出确认，你可以选择继续上传，或者换一个仓库。过大的仓库可能被 GitHub 提醒瘦身，具体政策以 GitHub 官方为准。
单个文件
单个文件最大 99MB，超过的会被跳过；超过 20MB 的文件 jsDelivr 不支持，会自动改用 GitHub raw 直链。
公开 / 私有
新建仓库时可以选公开或私有。已有的仓库，在「选择上传仓库」列表里点右侧的「公开」或「私有」标签就能切换，切换前会让你确认。改为私有后外部打不开里面的文件，已贴出去的直链会失效；改为公开后任何人都能看到仓库里的全部内容。
悬浮球里固定仓库
在悬浮球的仓库列表里长按某个仓库，它会固定在最前面；再长按一次取消固定。
插件
账号安全
Token 怎么选
Token 以明文保存在这台设备的浏览器里。建议在 GitHub 创建 fine-grained Token，只授权给你用来存图的那一个仓库，并只勾选读写内容所需的权限。这样即使泄露，影响范围也只有这一个仓库。要在 App 里新建、改名、删除仓库、切换公开 / 私有，Token 需要有仓库管理权限。
怀疑泄露时
立刻到 GitHub 的设置里删除这个 Token，再生成新的填进来。
